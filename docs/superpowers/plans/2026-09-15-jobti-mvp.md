# JOBTI MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a mobile-first, deterministic JOBTI autumn-recruitment personality test with a complete quiz, 24-personality scoring engine, result reveal, and 1080×1920 share poster.

**Architecture:** Static typed data in `data/` feeds pure scoring functions in `lib/scoring/`; the Next.js App Router renders the home, quiz, and result flows. Browser storage keeps a resumable answer state, while a client-only poster component converts a fixed 9:16 DOM tree to PNG.

**Tech Stack:** Next.js App Router, React, TypeScript, Tailwind CSS, Zod, Vitest, Playwright, html-to-image.

**Spec:** `/Users/yu/.codex/attachments/4d3da64d-2f8d-4ac1-bcbc-c402cbaac0dd/pasted-text.txt` (Product Spec v1.0)

## Global Constraints

- 30 real four-choice autumn-recruitment questions plus Q0 progress and start-month questions.
- Ten dimensions are normalized to 0–100 before personality matching.
- Hard gates run before a 70% vector similarity + 30% tag match + bonus score.
- Main and secondary personalities must come from different families.
- No login, backend, database, AI, leaderboard, or fabricated scannable QR code.
- Mobile-first, one-question-per-screen, autosave/resume, accessible touch targets, no horizontal overflow.

### Task 1: Typed data and scoring engine

Create package/config files and failing Vitest tests for normalization, gates, scoring, secondary personality, combinations, and storage-safe state. Implement the smallest pure modules and complete 24-personality data after the tests are observed failing.

### Task 2: Quiz flow and storage

Implement Q0, start-month, and 30-question screens with immediate advance, back/edit, conditional feedback, progress, and dual browser storage persistence.

### Task 3: Result reveal and report

Implement deterministic settling/reveal animation, report sections, attribute bars, reset action, and match wording that explicitly describes algorithmic matching rather than population percentile.

### Task 4: Poster and project docs

Implement fixed 1080×1920 poster generation/download/copy sharing, responsive visual system, README, Playwright smoke coverage, and a verification report containing fresh command evidence.
